# 화면 설계

> 입력: `docs/planner/requirements.md`, `user-flow.md`, `erd.md`
> 토큰과 컴포넌트 이름은 `design-system.md` 기준
> 상태: 초안

## 0. 공통 골격

### 0.1 전체 프레임
```
┌──────────────────────────────────────────────────────────────────────┐
│ purplemine    대본   견적서   보유 차량                  담당자 ▾      │ 상단 바 56px
├──────────────────────────────────────────────────────────────────────┤
│ (대본 하위 화면만) 분석 결과  ─  차량 매칭  ─  견적서                    │ 진행 단계 바 48px
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│   화면 제목 (h2)                                  [Primary 동작]      │
│   ────────────────────────────────────────────────────────────────   │
│   본문                                                                │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```
- 상단 바: 왼쪽 로고 텍스트 `purplemine`(600), 메뉴 3개는 현재 위치에 하단 2px `brand` 선. 오른쪽 담당자 메뉴(로그아웃). 로그인 도입 전(Q2)에는 담당자 메뉴 숨김.
- 배경 `paper`, 본문 패널은 `surface` + `border-default`.
- 화면 제목 오른쪽에 그 화면의 **Primary 버튼 하나**만 둔다. 나머지는 Secondary 이하.
- 대본 하위 화면(S-04~S-07)의 **진행 단계 바(`WorkflowStepper`)**: `분석 결과` → `차량 매칭` → `견적서`. 이 셋은 실제로 순서가 있는 작업이라 단계로 보여 준다.
  - 현재 단계: `brand` 글자 + 하단 선. 완료 단계: 체크 아이콘. 아직 못 가는 단계: `ink-faint`, 클릭 비활성(툴팁 "분석이 끝나면 볼 수 있습니다").
  - 단계 바 클릭은 흐름도의 [분석 결과로], [차량 매칭으로] 이동과 같은 동작이다.

### 0.2 공통 상태 패턴
| 상태 | 표현 |
|---|---|
| 불러오는 중 | 표/목록 자리에 행 모양 스켈레톤(`surface-sunken`), 움직임 없음 |
| 빈 목록 | `EmptyState` (design-system 5.14) |
| 불러오기 실패 | 패널 상단 오류 배너 "목록을 불러오지 못했습니다. 잠시 후 다시 시도해 주세요." + [다시 시도] |
| 저장 중 | 해당 버튼 로딩, 나머지 입력은 유지 |
| 저장 실패 | 오류 토스트(닫기 전까지 유지). 입력값은 그대로 보존 |

## 0.5 S-00 시작 화면 (`/`) — 추가 제안

기획 화면 목록에 없는 화면. 로그인 직후 바로 업로드 폼이나 목록이 나오면 "무슨 서비스인지"가 안 보여서, **자동차 렌트 회사의 서비스**임을 먼저 알리고 [견적 산출하기]로 업무를 시작하게 한다. 기획 확정이 필요하다(UX9).

### 레이아웃
```
 purplemine                              대본   견적서   보유 차량
 ─────────────────────────────────────────────────────────────────
  촬영에 필요한 차량,                    ┌─ 슬레이트 예시 ──────────┐
  대본만 올리면 견적까지                  │ 12  한강 주차장 밤        │
                                         │ [차 일러스트]             │
  드라마와 영화 촬영용 차량을 빌려드립니다. │ [12가 3456] ●주인공 ⚡추격 │
  대본을 올리면 ...                       └──────────────────────────┘
  [견적 산출하기]  [보유 차량 보기]
  자동으로 찾은 내용은 담당자가 검토하고 고칠 수 있습니다.

  이렇게 진행됩니다   1 대본 올리기   2 필요한 차량 확인   3 견적서 받기
  보유 차량            24 세단   18 SUV   9 승합   7 트럭   5 스포츠카   6 클래식
```
- 왼쪽: 한 문장 제목(h1 40px), 설명 두 문장, Primary lg [견적 산출하기], Secondary lg [보유 차량 보기].
- 오른쪽: 서비스가 하는 일을 보여 주는 예시 패널. 씬 번호, 장소, 차량 일러스트, 번호판 칩, 역할/용도 태그, 일 단가. 실제 데이터가 아니라 고정된 예시다.
- 아래: "이렇게 진행됩니다"는 실제 순서(3단계)라 번호를 쓴다. "보유 차량"은 분류별 대수(실제 DB 값으로 대체). 이 구간은 화면 아래로 내려야 보이는 보조 정보다.
- 상단 로고를 누르면 항상 이 화면으로 돌아온다.

### 이동
| 요소 | 이동 |
|---|---|
| [견적 산출하기] | S-03 대본 업로드 |
| [보유 차량 보기], 메뉴 [보유 차량] | S-09 |
| 메뉴 [대본], [견적서] | S-02, S-08 |

진행 중인 대본이 있으면 히어로 아래에 "진행 중인 대본" 한 줄(작품명, 상태 뱃지, [이어서 보기])을 추가하는 안을 검토한다. 이 경우 S-02 대시보드와 역할이 겹치므로 UX9에서 함께 결정.

## 1. S-03 대본 업로드 (`/scripts/new`)

**이 화면의 일**: 담당자가 대본 파일과 기본 정보를 넣고 분석을 시작한다. 입력은 최소로 하고, 올리면 바로 분석이 시작된다는 것을 분명히 한다.

### 레이아웃
```
 대본 업로드

 ┌──────────────────────────────────────┐  ┌────────────────────────┐
 │ 대본 파일 (필수)                      │  │ 올릴 수 있는 파일       │
 │ ┌──────────────────────────────────┐ │  │ PDF, DOCX, TXT         │
 │ │                                  │ │  │ 파일당 최대 ○○MB        │
 │ │   파일을 여기에 끌어다 놓거나     │ │  │                        │
 │ │   [파일 선택]                     │ │  │ 업로드하면 바로 분석이   │
 │ │                                  │ │  │ 시작됩니다. 분석 중에도  │
 │ └──────────────────────────────────┘ │  │ 다른 화면으로 이동할 수  │
 │                                      │  │ 있습니다.               │
 │ 작품명 (필수)                         │  │                        │
 │ [______________________________]     │  │ 대본은 기밀 자료로       │
 │ 제작사 (필수)                         │  │ 취급됩니다. 삭제하면     │
 │ [______________________________]     │  │ 원본과 분석 결과가 함께  │
 │ 촬영 예정 기간                        │  │ 삭제됩니다.             │
 │ [2026.__.__] ~ [2026.__.__]          │  └────────────────────────┘
 │ 알고 있다면 입력하세요. 비워 두면      │
 │ 대본에서 일정 단서를 찾아봅니다.       │
 │                                      │
 │ ─────────────────────────────────    │
 │              [취소]   [업로드]        │
 └──────────────────────────────────────┘
```
- 폼 컬럼 너비 640px, 오른쪽 안내 컬럼 320px(desktop 이상). tablet 이하에서는 안내가 폼 아래로 이동.
- 폼은 한 열로만 쌓는다. 날짜 두 칸만 한 줄.
- 안내 컬럼은 `border-default` 없는 평면(배경 `surface-sunken`, `radius-data`, 패딩 24). 제목 라벨은 쓰지 않고 문장으로 시작.
- 최대 용량과 형식은 Q4 결정 전까지 자리표시(○○MB)로 두고, 확정되면 문구 교체.

### 컴포넌트 구성
| 영역 | 컴포넌트 | 비고 |
|---|---|---|
| 파일 | `FileDropzone` | 높이 160, 점선 `line-strong` 테두리, 드래그 중 테두리 `brand` + 배경 `brand-soft` |
| 입력 | `TextField` × 2, `DateRangeField` | 작품명/제작사 필수 |
| 하단 | Secondary [취소], Primary [업로드] | 오른쪽 정렬, 폼 하단 구분선 위 24px |

### 상태
| 상태 | 표현 | 문구 |
|---|---|---|
| 기본 | [업로드] 활성. 필수값이 비면 누를 때 오류 표시(미리 비활성화하지 않음) | |
| 파일 선택됨 | 드롭존이 파일 행으로 바뀜: 파일 아이콘, 파일명, 용량, [삭제] 아이콘 버튼 | |
| 업로드 중 | 파일 행에 진행 막대, [업로드] 로딩, [취소]는 업로드 취소 | |
| 형식 오류 | 드롭존 아래 오류 | "PDF, DOCX, TXT 파일만 올릴 수 있습니다. 다른 형식이면 변환 후 다시 올려 주세요." |
| 용량 초과 | 같은 위치 | "파일이 ○○MB를 넘습니다. 파일을 나누거나 용량을 줄여 다시 올려 주세요." |
| 필수값 누락 | 해당 입력 아래 오류, 첫 오류에 포커스 | "작품명을 입력해 주세요." |
| 기간 오류 | 날짜 입력 아래 | "종료일이 시작일보다 앞섭니다." |
| 서버 오류 | 상단 오류 배너, 입력값 유지 | "업로드하지 못했습니다. 입력한 내용은 그대로 두었습니다. 다시 시도해 주세요." |
| 성공 | S-04로 이동. 토스트 "업로드했습니다. 분석을 시작합니다." | |

### 이동
[업로드] 성공 → S-04. [취소] → S-02. 입력 중 이탈 시 확인: "입력한 내용이 사라집니다. 나갈까요?" [나가기] / [계속 입력]

## 2. S-04 대본 상세 (`/scripts/:id`) — 분석 진행 포함

업로드 직후 도착하는 화면이라 분석 중 상태를 여기서 설계한다. (요청 범위의 4개 주요 화면 중 하나는 아니지만 흐름상 필요)

### 레이아웃
```
 서울의 밤                                      [재분석]  [삭제]
 제작사 한빛스튜디오   촬영 예정 2026.11.03 ~ 2026.11.21   업로드 2026.10.19

 ┌─ 분석 진행 ───────────────────────────────────────────────────────┐
 │  ✓ 텍스트 추출      ✓ 씬 분할      ◌ 차량 추출      ○ 차량 매칭     │
 │  ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░░░░░░░░░                                  │
 │  차량 요구사항을 찾는 중입니다. 다른 화면으로 이동해도 분석은 계속됩니다.│
 └───────────────────────────────────────────────────────────────────┘
                                         [분석 결과 보기] (비활성)
```
- 메타 정보는 라벨 없는 한 줄(작품명 아래). 항목 사이는 간격 24px로 구분하고 가운뎃점이나 구분 기호를 쓰지 않는다. 각 항목은 `ink-muted` 라벨 + `ink` 값을 한 쌍으로 묶는다.
- 분석 진행의 4단계는 실제 파이프라인 순서(텍스트 추출 → 씬 분할 → 차량 추출 → 차량 매칭)라 번호 없이 `StageBar`로 표시. `aria-live="polite"`로 단계 변화를 읽어 준다.
- 단계 표시: 완료 ✓(성공색), 진행 중 스피너(`brand`), 대기 ○(`ink-faint`).
- 이 화면의 **유일한 자동 모션**: 분석이 끝나면 완료 체크가 순서대로 찍히고 [분석 결과 보기]가 Primary로 활성화된다.

### 상태
| 상태 | 표현 |
|---|---|
| 대기(UPLOADED) | 뱃지 "대기", 문구 "곧 분석을 시작합니다." |
| 분석 중(ANALYZING) | 위 레이아웃. [분석 결과 보기]·[재분석] 비활성 |
| 완료(ANALYZED) | 뱃지 "분석 완료". 요약 3칸: 씬 개수, 차량 요구 개수, 확인 필요 개수(숫자는 Big Shoulders 36). [분석 결과 보기] Primary. 견적서가 있으면 [견적서 보기] Secondary |
| 실패(FAILED) | 오류 배너 "분석에 실패했습니다. 대본 파일에 문제가 없는지 확인하고 다시 분석해 주세요." + [재분석]. 실패한 단계는 오류색 표시 |
| 재분석 | 확인 모달: 제목 "다시 분석합니다", 본문 "지금까지 수정한 내용 ○건이 사라집니다." [다시 분석] / [취소]. 수정 내용이 없으면 모달 생략 |

## 3. S-05 분석 결과 (`/scripts/:id/analysis`)

**이 화면의 일**: LLM이 대본에서 뽑은 씬과 차량 요구사항을 담당자가 **빠르게 훑고, 의심스러운 것만 고치는** 곳. 자동 확정은 없다.

### 레이아웃
```
 서울의 밤                                              [차량 매칭으로]
 [분석 결과]─────[차량 매칭]─────[견적서]

 씬 38개     차량 요구 52건     확인 필요 7건     수정함 3건

 필터: [전체] [확인 필요 7] [수정함 3]    역할 ▾   용도 ▾   [요구사항 추가]
 ┌────────────────────────────────────────────────────────────────────┐
 │ 12  한강 주차장                          밤        차량 요구 2건  ⌃ │
 │     주인공이 차에서 내려 전화를 받는다.                              │
 │     ┌──────────────────────────────────────────────────────────┐  │
 │     │역할     차종 요구        대수 용도     파손   신뢰도       │  │
 │     │●주인공  검정 대형 세단   1   ⚡추격    예     ⚠확인 필요 ⋯│  │
 │     │ ┃ “…그는 검은 [제네시스 G90]에서 내려 번호판을 가렸다.”      │  │
 │     │ ┃  원문 12번 씬 중          [원문 보기]                     │  │
 │     │◐조연    경차             2   ☐일반     아니오 ✓높음      ⋯│  │
 │     └──────────────────────────────────────────────────────────┘  │
 ├────────────────────────────────────────────────────────────────────┤
 │ 13  편의점 앞                            낮        차량 없음       ⌄ │
 ├────────────────────────────────────────────────────────────────────┤
 │ 14  ...                                                            │
 └────────────────────────────────────────────────────────────────────┘
 ──────────────────────────────── (하단 고정 바)
  확인 필요 7건이 남아 있습니다.                      [차량 매칭으로]
```

### 구조
- **씬 목록**: 한 씬 = 한 행 묶음. 왼쪽에 `SceneNumber`(56px 폭), 오른쪽에 장소(h4), 시간대(낮/밤 텍스트 태그), 한 줄 요약(`ink-muted`, 1줄 말줄임). 맨 오른쪽 요구 개수와 펼침 아이콘.
- **펼침 기본값**: 확인 필요/낮음이 있는 씬은 처음부터 펼침, 나머지는 접힘. 필터를 바꾸면 해당 조건이 있는 씬만 보이고 펼침.
- **요구사항 표** (씬 안): 열 = 역할(`RoleTag`) / 차종 요구 / 대수 / 용도(`UsageTag`) / 파손 / 신뢰도(`Confidence`) / 더보기.
  - 차종 요구는 대본 표현("검정 대형 세단")을 크게, 대본에 명시된 차명(`brand_model_hint`)이 있으면 아래 줄에 `ink-muted` 로 "대본 명시: 제네시스 G90".
  - 행 클릭(또는 Enter)으로 행 아래에 `SourceQuote`가 펼쳐진다(F-14).
- **원문 드로어**: [원문 보기] → 오른쪽 드로어(480px)에 해당 씬 전체 원문. 차량 언급 구간 형광펜, 다른 요구사항의 구간은 옅은 밑줄. 드로어를 열어 둔 채 표를 계속 편집할 수 있다(모달 아님, 배경 막 없음).
- **요약 4칸**: 상단 한 줄. 숫자(Big Shoulders 28) + 라벨. 클릭하면 아래 필터와 같은 효과.
- **하단 고정 바**: 화면 하단에 붙은 한 줄(`surface`, 위 선 `line`). 남은 확인 필요 건수와 [차량 매칭으로]. 건수가 0이면 문구가 "모든 항목을 확인했습니다."로 바뀐다.

### 편집 (F-15)
| 동작 | 방식 |
|---|---|
| 값 수정 | 셀 클릭 → 인라인 입력. 역할/용도는 드롭다운, 대수는 숫자 스테퍼, 파손은 토글. Enter 저장, ESC 취소. 저장되면 행에 "수정함" 표시가 붙고 신뢰도 자리를 대체 |
| 요구사항 추가 | 씬 오른쪽 위 [요구사항 추가] (Ghost) 또는 "차량 없음" 씬의 같은 버튼. 빈 행이 열리고 차종 요구에 포커스. 배경 차량 누락(Q10)을 위해 씬마다 항상 노출 |
| 삭제 | 더보기(⋯) → [삭제]. 확인 없이 삭제하고 토스트에 [되돌리기]를 제공(5초) |
| 확인 완료 | 신뢰도가 "확인 필요/낮음"인 행의 더보기에 [확인함]. 누르면 신뢰도 표시가 "확인함"(체크, 중립)으로 바뀌어 남은 건수에서 빠진다 |
| 씬 수정 | 씬 헤더의 장소/시간대/요약도 같은 방식으로 인라인 수정(씬 추가/삭제는 이번 범위 제외) |

### 상태
| 상태 | 표현 |
|---|---|
| 분석 미완료 | 이 화면에 직접 들어오면 안내 배너 "아직 분석 중입니다." + [대본 상세로] |
| 차량 요구 0건 (전체) | 빈 상태: "차량이 필요한 씬을 찾지 못했습니다" / "씬마다 요구사항을 직접 추가할 수 있습니다." / [요구사항 추가] |
| 필터 결과 없음 | 표 자리에 "조건에 맞는 항목이 없습니다." + [필터 해제] |
| 저장 실패 | 해당 행 아래 오류 한 줄 "저장하지 못했습니다. 다시 시도" 링크. 입력값은 유지 |

### 이동
[차량 매칭으로] → S-06. 단계 바 "분석 결과/차량 매칭". 대본 상세는 화면 제목 위 이동 경로("대본 목록 > 서울의 밤")로.

## 4. S-06 차량 매칭 (`/scripts/:id/matching`)

**이 화면의 일**: 요구사항마다 RAG가 제시한 후보 차량 중 **무엇을 쓸지 정한다**. 왜 그 차가 후보인지 한눈에 읽혀야 한다.

### 레이아웃
```
 서울의 밤                                              [견적서 생성]
 [분석 결과]─────[차량 매칭]─────[견적서]

 요구사항 52건     선택 완료 38건     후보 없음 3건     선택 전 11건
 필터: [전체] [선택 전] [후보 없음]      가용 일정은 직접 확인해 주세요.

 ┌────────────────────────────────────────────────────────────────────┐
 │ 12   ●주인공  검정 대형 세단 1대   ⚡추격   파손 예정                  │
 │      원문: “…검은 제네시스 G90에서 내려…”                  [원문 보기] │
 │      필요 1대, 선택 0대                                             │
 │ ┌──────────────┐ ┌──────────────┐ ┌──────────────┐                │
 │ │[12가 3456]   │ │[34나 7890]   │ │[56다 1122]   │                │
 │ │G90 2023 검정 │ │G80 2022 검정 │ │K9 2021 검정  │                │
 │ │▓▓▓▓▓▓▓▓░ 92 │ │▓▓▓▓▓▓▓░░ 84 │ │▓▓▓▓▓▓░░░ 71 │                │
 │ │일 220,000원  │ │일 180,000원  │ │일 150,000원  │                │
 │ │차명이 대본과 │ │같은 급 대형  │ │대형 세단, 색 │                │
 │ │일치, 파손    │ │세단, 색 일치 │ │일치. 파손    │                │
 │ │촬영 가능     │ │              │ │촬영 불가 ⚠   │                │
 │ │ [선택]       │ │ [선택]       │ │ [선택]       │                │
 │ └──────────────┘ └──────────────┘ └──────────────┘   [다른 차량 찾기]│
 ├────────────────────────────────────────────────────────────────────┤
 │ 12   ◐조연  경차 2대   일반 주행                                    │
 │      ...                                                            │
 └────────────────────────────────────────────────────────────────────┘
```

### 구조
- **요구사항 블록**: 한 요구사항 = 한 블록(위 구분선 `line`). 블록 머리에 씬 번호(`SceneNumber` 32px 축소), `RoleTag`, 차종 요구, 대수, `UsageTag`, 파손 예정이면 위험색 태그. 그 아래 한 줄 원문 요약과 [원문 보기].
- **씬 번호 묶기**: 같은 씬의 요구사항이 연달아 나오면 번호는 첫 블록에만 보이고 나머지는 자리만 비워 정렬을 유지.
- **필요/선택 대수**: "필요 3대, 선택 1대". 대수가 2 이상이면 후보를 여러 대 선택할 수 있다(ERD상 한 요구사항에 선택 여러 건 가능). 선택 수가 필요 수에 닿으면 나머지 카드의 [선택]은 비활성(툴팁 "필요한 대수를 모두 선택했습니다").
- **후보 카드** (`CandidateCard`, 너비 240, 최대 3장 가로 나열, 4번째 이후는 [후보 더 보기]):

| 영역 | 내용 |
|---|---|
| 1줄 | `PlateChip` |
| 2줄 | 브랜드 모델, 연식, 색상 (`body` 500) |
| 3줄 | `ScoreBar` + 점수 |
| 4줄 | 일 단가 `150,000원` (탭 숫자) |
| 5~6줄 | 매칭 사유 최대 3줄 말줄임, 전체는 호버/포커스 툴팁 |
| 경고 | 파손 불가 차량인데 파손 요구가 있으면 사유 아래 주의 한 줄 `파손 촬영 불가` |
| 버튼 | [선택] Secondary → 선택되면 [선택됨] (체크, `brand-soft` 배경, `brand` 테두리 2px). 다시 누르면 해제 |

  - 카드는 평면(그림자 없음), 테두리 `border-default`. 선택된 카드만 테두리가 `brand` 2px.
  - 후보 순서는 점수 내림차순. 가장 높은 후보를 **자동 선택하지 않는다**(담당자가 눌러야 함).
- **[다른 차량 찾기]** (Ghost, 블록 오른쪽 아래): 모달(720px)에서 전체 보유 차량 검색. 검색창(차종·번호·색상), 필터(분류, 파손 가능), 표(번호판 칩, 차종, 분류, 일 단가, 파손 가능). 행 선택 후 [이 차량 선택] 누르면 후보 목록 끝에 "직접 선택"으로 추가·선택. 모달 제목 "차량 선택".
- **상단 요약 4칸**: 요구사항 전체, 선택 완료, 후보 없음, 선택 전. 클릭 시 필터.
- **일정 안내**: 필터 줄 오른쪽에 `ink-muted` 안내 "가용 일정은 직접 확인해 주세요." 가용 일정을 시스템이 관리하게 되면(Q9) 후보 카드에 겹침 경고를 추가하고 이 안내는 제거.

### 상태
| 상태 | 표현 |
|---|---|
| 후보 있음, 선택 전 | 위 레이아웃 |
| 후보 없음 | 카드 자리에 점선 박스 (높이 80): "같은 조건의 보유 차량을 찾지 못했습니다." + [다른 차량 찾기] (Secondary로 승격) |
| 일부 후보 점수 낮음 | 모든 후보가 50점 미만이면 블록 머리 오른쪽에 주의 태그 "일치도 낮음" |
| 선택 완료 | 블록 머리 오른쪽에 성공 태그 "선택 완료". 카드는 그대로 두고 선택된 카드만 강조 (접지 않는다. 바꾸기 쉽게) |
| 불러오기 중 | 블록 스켈레톤: 머리 한 줄 + 카드 3장 자리 |
| 선택 저장 실패 | 카드 아래 오류 한 줄, 선택 상태는 이전 값으로 되돌림 |

### 하단 고정 바와 [견적서 생성]
- 하단 고정 바: "요구사항 52건 중 38건을 선택했습니다." + Primary [견적서 생성].
- 선택 전/후보 없음이 남은 채 생성하는 것은 허용한다(U4 가정). 클릭 시 확인 모달: 제목 "견적서를 만듭니다", 본문 "차량을 정하지 못한 요구사항 14건은 '차량 미정' 항목으로 들어갑니다. 견적서에서 직접 채울 수 있습니다." [견적서 생성] / [계속 선택]. 14건이 0이면 모달 없이 바로 생성.
- 생성 중: 버튼 로딩. 성공하면 S-07로 이동.

### 이동
[견적서 생성] → S-07. 단계 바 "분석 결과"로 돌아가기. 매칭 중 분석 결과를 고치면 후보가 달라질 수 있어, 돌아와서 수정한 요구사항 블록에 "요구사항이 수정되었습니다. 후보를 다시 찾으시겠습니까?" 배너 + [후보 다시 찾기]를 보여 준다.

## 5. S-07 견적서 상세/편집 (`/quotes/:id`)

**이 화면의 일**: 확정된 매칭으로 만든 견적서를 검토하고 숫자를 고쳐서 제작사에 보낼 수 있는 상태로 만든다. 숫자가 틀리지 않았다는 확신을 주는 화면이다.

### 레이아웃
```
 서울의 밤 견적서                           (저장되지 않은 변경 3건)
 Q-2026-0142   v2  [초안]         [상태 변경 ▾]  [내보내기 ▾]  [저장]
 [분석 결과]─────[차량 매칭]─────[견적서]

 ┌───────────────────────────────────────────────┐ ┌──────────────────┐
 │ 작품명      서울의 밤        작성일   2026.10.19 │ │ 공급가액          │
 │ 제작사      한빛스튜디오     유효기간 [2026.11.18]│ │      12,480,000원 │
 │ 촬영 기간   [2026.11.03] ~ [2026.11.21] (19일)  │ │ 부가세 10%        │
 │ 담당자      김민지           부가세  [별도 ▾]    │ │       1,248,000원 │
 └───────────────────────────────────────────────┘ │ ───────────────── │
                                                   │ 합계              │
 차량 항목 14건                      [항목 추가]    │  13,728,000원     │
 ┌───────────────────────────────────────────────┐ │ (Big Shoulders 48)│
 │ 차량 / 대수 / 기간 / 일 단가 / 추가 비용 / 소계  │ │                   │
 ├───────────────────────────────────────────────┤ │ [내보내기]         │
 │ [12가 3456] 제네시스 G90 2023 검정               │ └──────────────────┘
 │ 1대  11.03 ~ 11.07 (5일)  220,000  보험 +50,000 1,150,000 ⋯│  (오른쪽 패널은 스크롤 시 고정)

 │ 메모: 파손 위험 할증 별도 협의                      │
 ├───────────────────────────────────────────────┤
 │ [번호 미정] 차량 미정 (경차 2대 필요)       ⚠ 차량 선택 │
 │ ...                                             │
 └───────────────────────────────────────────────┘

```

### 구조
- **헤더 줄**: 제목 "{작품명} 견적서"(h2). 아래 견적서 번호(`Q-2026-0142`), 버전 칩(`v2`), 상태 뱃지. 오른쪽에 [상태 변경] (Secondary 드롭다운), [내보내기] (Secondary 드롭다운: PDF / 엑셀), [저장] (Primary).
- **저장 안 된 변경**: 제목 줄 오른쪽에 주의색 텍스트 "저장되지 않은 변경 3건". 이탈 시 확인: "저장하지 않은 변경 3건이 사라집니다." [저장하고 나가기] / [버리고 나가기] / [계속 편집].
- **본문 2열**: 왼쪽 문서 영역(가변), 오른쪽 합계 패널(너비 320, `position: sticky; top: 120px`). tablet 이하에서는 합계 패널이 문서 영역 위로 올라가 한 줄 요약(합계만)으로 접힘.
- **견적서 정보 패널**: 2열 정의 목록(라벨 `ink-muted`, 값 `ink`). 작품명/제작사/담당자/작성일은 읽기 전용, 촬영 기간/유효기간/부가세 기준은 편집 가능. 촬영 기간을 바꾸면 항목 기간과의 불일치를 알린다(아래).
- **합계 패널**: `surface` 패널(그림자 없음). 공급가액, 부가세, 구분선, 합계. 합계만 `--numeral-total`(Big Shoulders 48)로 크게. 단위 "원"은 18px로 뒤에. 값이 바뀌면 0.6초 `brand-soft` 깜빡임.
- **차량 항목 표**: 한 항목을 **두 줄 행**으로 보여 준다(열이 많아서 한 줄이면 가로 스크롤이 생기기 때문).

| 줄 | 내용 |
|---|---|
| 1줄 (편집 가능한 숫자) | 차량(`PlateChip` + 차종 연식 색상) / 대수 / 기간(시작 ~ 종료, 일수) / 일 단가 / 추가 비용 / 소계(읽기 전용, 굵게) / 더보기 |
| 2줄 (맥락, `ink-muted`) | `RoleTag`, `UsageTag`, 연결 씬 번호들 "씬 12, 14, 15", 매칭 메모 |

  - 열 폭(desktop 기준 문서 영역 ~900px): 차량 280 / 대수 56 / 기간 200 / 일 단가 96 / 추가 비용 120 / 소계 112 / 더보기 36.
  - 숫자 셀은 `EditableCell`(오른쪽 정렬). 기본 단가와 달라진 경우 셀 아래에 `caption`으로 "기본 220,000원" 표시(원래 값을 잃지 않게).
  - 소계 = 단가 × 대수 × 일수 + 추가 비용. 계산식은 소계 셀 호버/포커스 툴팁에 풀어서 보여 준다: "220,000 × 1대 × 5일 + 50,000".
  - **추가 비용 셀**: 클릭하면 팝오버(320px)가 열린다. 행 = 항목명(보험, 운전기사, 탁송, 파손 위험 할증 중 선택 또는 직접 입력) + 금액, [항목 추가]. 셀에는 합계 금액과 개수 "+50,000 (1)"가 표시된다. 항목 범위는 Q5/E4 결정에 따라 조정.
  - **더보기(⋯)**: [메모 편집], [항목 복제], [항목 삭제].
  - 열 제목 줄은 스크롤해도 문서 영역 상단에 고정(`position: sticky`).
- **차량 미정 항목**: 행 배경 `warning-bg`, 차량 칸에 `번호 미정` 칩 + "차량 미정" + 요구 내용("경차 2대 필요") + Secondary 소버튼 [차량 선택]. 모달은 S-06의 "차량 선택"과 같은 컴포넌트. 차량이 정해지기 전에는 단가 입력 가능(수동 단가), 합계에는 입력된 금액만 포함. 상단에 주의 배너 "차량을 정하지 못한 항목이 2건 있습니다."
- **항목 추가**: [항목 추가] → 모달 "차량 선택"으로 보유 차량 선택(요구사항 없이 수동 추가, `requirement_id` 없음). 기간은 촬영 기간 전체로 기본 입력.
- **기간 불일치**: 항목 기간이 견적서 촬영 기간 밖이면 해당 기간 셀에 주의 아이콘 + 툴팁 "촬영 기간(11.03 ~ 11.21)을 벗어났습니다."
- **비고**: 여러 줄 입력, 너비 문서 영역 전체.

### 상태 변경 (F-34)
- [상태 변경] 드롭다운은 현재 상태의 다음 단계만 활성: 초안 → 검토중 → 발송 → 확정. 되돌리기는 "초안으로 되돌리기" 별도 항목.
- 확정 처리 시 확인 모달: 제목 "견적서를 확정합니다", 본문 "확정하면 수정할 수 없습니다. 다시 수정하려면 새 버전을 만들어야 합니다." [확정] / [취소]. (버전 정책은 E2 결정 후 문구 확정)
- **확정/발송 상태**: 모든 편집 셀 읽기 전용(점선 밑줄 제거), 상단 정보 배너 "발송한 견적서는 수정할 수 없습니다." + [새 버전 만들기]. [저장]은 숨김.

### 상태
| 상태 | 표현 |
|---|---|

### 인쇄/내보내기 레이아웃
회사 양식(Q8)이 정해지기 전까지 화면과 같은 구조(정보, 항목표, 합계, 비고)를 A4 가로 한 장 기준으로 단순 배치. 번호판 칩은 일반 텍스트로 풀고, 색은 흑백 인쇄 시에도 읽히게 상태 아이콘과 텍스트를 유지.

## 6. 그 외 화면 (요약)

주요 4개 외 화면은 같은 컴포넌트를 재사용한다. 상세 레이아웃은 필요 시 추가.

| 화면 | 구성 요약 |
|---|---|
| S-01 로그인 | 가운데 정렬, 너비 360 폼 패널. 이메일, 비밀번호, [로그인]. 실패: 폼 위 오류 "이메일 또는 비밀번호가 맞지 않습니다." (Q2 결정 전까지 보류) |
| S-02 대시보드 (대본 목록) | 제목 "대본" + Primary [새 대본 업로드]. 필터 줄(상태 칩, 검색). `DataTable`: 작품명 / 제작사 / 촬영 예정 / 상태 뱃지 / 확인 필요 건수 / 견적서(있으면 번호) / 업로드일. 행 클릭 → S-04. 분석 중 행은 뱃지 스피너, 목록 상단에서 주기 갱신. 빈 상태: "아직 업로드한 대본이 없습니다" |

## 7. 반응형 동작 요약

| 화면 | desktop (≥1024) | tablet (640~1023) | mobile (<640) |
|---|---|---|---|
| S-03 | 폼 + 안내 2열 | 안내가 폼 아래로 | 1열, 날짜 두 칸은 세로로 |
| S-05 | 씬 목록 + 필요 시 드로어 | 드로어는 전체 폭 시트 | 요구사항 표가 행당 3줄 카드로 바뀜. 인라인 편집은 탭 시 시트에서 |
| S-06 | 후보 카드 3장 가로 | 카드 2장 + 가로 스크롤 | 카드 1장씩 세로 스택, 점수·단가는 한 줄로 |
| S-07 | 문서 + 합계 패널 2열 | 합계 패널이 위로 이동 | 항목이 카드형으로, 합계는 하단 고정 바. 편집은 가능하지만 조회 중심 |

공통: 상단 메뉴는 mobile에서 햄버거로 접힌다. 하단 고정 바는 mobile에서도 유지하되 버튼 높이 48.
