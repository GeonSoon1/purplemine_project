> 대본 → 차량 렌트 견적서 서비스의 색, 타이포, 간격, 컴포넌트 토큰

## 1. 디자인 방향

**사용자는 렌트 회사 견적 담당자.** 하루 종일 표와 숫자를 보고, LLM이 뽑은 결과를 한 줄씩 검증하고, 금액을 고친다. 장식보다 *읽기 쉬움*, *검증하기 쉬움*, *숫자가 정확해 보임*이 우선이다.

**세계관은 촬영 현장의 문서.** 콜시트, 슬레이트(씬 번호판), 대본 여백의 메모, 차량 번호판. 이 어휘에서 시각 요소를 가져온다.

**기억에 남기는 요소는 두 가지만 쓴다.**
1. **씬 번호**: 슬레이트처럼 크고 굵은 숫자(Big Shoulders Display)로 씬을 구분한다. 씬은 실제로 순서가 있는 단위라 번호가 정보다.
2. **번호판 칩**: 차량 식별자를 한국 번호판 모양으로 보여 준다. 사진이 없는 데이터(ERD에 이미지 없음)에서 차량을 한눈에 구분하는 시각 앵커 역할을 한다.

나머지는 조용하게 둔다. 흰 면, 얇은 선, 보라 한 가지.

### 의도적으로 피한 것
| 피한 기본값 | 대신 한 것 |
|---|---|
| 크림 배경 + 세리프 + 테라코타 | 살짝 푸른 기가 도는 라일락 회백 배경, 산세리프 |
| 검정 배경 + 형광 포인트 | 밝은 배경, 브랜드 보라(프로젝트명 purplemine) |
| 모든 것을 같은 둥근 카드 + 회색 그림자로 분할 | 표와 선으로 구조를 만들고, 그림자는 떠 있는 레이어(모달, 팝오버)에만 |
| 대문자 영문 라벨, 제목 위 소제목 | 라벨은 한글 문장형. 제목 위 장식 라벨 없음 |
| 모든 버튼 뒤 `→` | 버튼은 동사만 |
| 작은 데이터 라벨용 모노스페이스 | 숫자는 탭 숫자(tabular-nums) 지원 산세리프 |
| `01 / 02 / 03` 장식 번호 | 번호는 씬 번호, 분석 단계처럼 진짜 순서일 때만 |

## 3. 타이포그래피

### 3.1 서체
| 역할 | 서체 | 이유 |
|---|---|---|
| UI 전체, 본문, 제목 | **IBM Plex Sans KR** (400, 500, 600, 700) | 한글이 단정하고 숫자가 표에서 정돈되어 보임. 업무 도구의 신뢰감. 기본 한글 UI 서체(Pretendard 등)를 쓰지 않는 선택 |
| 씬 번호, 큰 합계 금액 | **Big Shoulders Display** (700, 800) | 슬레이트와 도로 표지판 같은 좁고 단단한 숫자. 숫자와 영문 전용이라 한글에는 쓰지 않음 |

폴백: `"IBM Plex Sans KR", "Noto Sans KR", "Apple SD Gothic Neo", "Malgun Gothic", system-ui, sans-serif` / `"Big Shoulders Display", "IBM Plex Sans KR", sans-serif`

Next.js에서는 `next/font/google`로 로드하고 `display: swap`을 쓴다.

### 3.2 크기 스케일
| 토큰 | 크기 / 줄간격 | 굵기 | 용도 |
|---|---|---|---|
| `--text-caption` | 12 / 16 | 400, 500 | 표 보조 정보, 도움말 |
| `--text-small` | 13 / 20 | 400, 500 | 표 셀(밀도 높은 표), 태그 |
| `--text-body` | 14 / 22 | 400 | UI 기본 |
| `--text-reading` | 16 / 26 | 400 | 대본 원문 인용(읽는 글) |
| `--text-h4` | 18 / 26 | 600 | 패널 제목, 씬 장소 |
| `--text-h3` | 22 / 30 | 600 | 섹션 제목 |
| `--text-h2` | 28 / 36 | 700 | 화면 제목 |
| `--text-h1` | 36 / 44 | 700 | 로그인, 빈 화면의 큰 제목 |
| `--numeral-scene` | 40 / 40 | 800 (Big Shoulders) | 씬 번호 |
| `--numeral-total` | 48 / 48 | 700 (Big Shoulders) | 견적서 합계 금액 |

규칙
- 한글 본문 줄간격은 1.5 이상. 원문 인용은 1.6.
- 본문 한 줄은 **70자 이내**. 원문 인용 블록은 `max-width: 68ch`.
- 숫자 열은 `font-variant-numeric: tabular-nums`, 오른쪽 정렬.
- 한글 제목은 `letter-spacing: -0.01em`, 본문은 0. 본문에 `word-break: keep-all`을 쓰고 긴 URL/파일명만 `overflow-wrap: anywhere`.
- 굵기는 400(본문), 500(강조 라벨), 600(제목), 700(화면 제목). 이탤릭은 쓰지 않는다(한글에 이탤릭이 없음).
- 제목에서 한 단어만 색을 바꾸거나 굵게 하는 장식은 하지 않는다.

### 3.3 숫자 표기
- 금액: `1,234,567원` (천 단위 쉼표, 단위 `원`은 작은 크기로 뒤에). 큰 합계만 Big Shoulders.
- 날짜: `2026.10.19` (표), 기간은 `2026.11.03 ~ 2026.11.21 (19일)`.
- 씬 번호: `S12`처럼 접두어 없이 숫자만 크게 쓰고, 목록 문맥에서만 "씬 12"로 읽힌다. 스크린 리더에는 `aria-label="씬 12"`.

## 4. 간격과 레이아웃

### 4.1 간격 (4px 기준)
| 토큰 | 값 | 용도 |
|---|---|---|
| `--space-1` | 4px | 아이콘과 텍스트 사이 |
| `--space-2` | 8px | 태그 내부, 촘촘한 요소 사이 |
| `--space-3` | 12px | 표 셀 가로 패딩, 입력 내부 |
| `--space-4` | 16px | 컴포넌트 기본 간격, 모바일 좌우 여백 |
| `--space-6` | 24px | 패널 내부 패딩, 그리드 거터 |
| `--space-8` | 32px | 데스크톱 페이지 좌우 여백, 섹션 사이 |
| `--space-12` | 48px | 큰 섹션 사이 |
| `--space-16` | 64px | 빈 화면 상하 여백 |

### 4.2 그리드와 중단점
| 구간 | 너비 | 동작 |
|---|---|---|
| mobile | < 640 | 1열. 표는 항목별 2~3줄 카드형으로 전환. 보기와 간단한 확인용이며 편집은 데스크톱 기준 |
| tablet | 640 ~ 1023 | 사이드 패널은 아래로 내려감 |
| desktop | 1024 ~ 1439 | 기본 설계 기준. 12열, 거터 24 |
| wide | ≥ 1440 | 콘텐츠 최대 너비 1280, 가운데 정렬 |

- 정렬: 텍스트는 **왼쪽 정렬**, 숫자 열은 **오른쪽 정렬**. 가운데 정렬은 빈 화면과 로그인에만.
- 페이지 좌우 여백 32px(모바일 16px).
- 상단 바 높이 56px, 고정. 대본 하위 화면에서는 그 아래에 진행 단계 바(높이 48px) 추가.

### 4.3 모서리와 선, 그림자
구조는 선으로 만들고, 모서리는 **위계별로 다르게** 쓴다.

| 토큰 | 값 | 대상 |
|---|---|---|
| `--radius-data` | 4px | 표, 번호판 칩, 원문 인용 블록, 입력 |
| `--radius-control` | 6px | 버튼, 드롭다운 |
| `--radius-overlay` | 12px | 모달, 팝오버, 드로어 |
| `--radius-pill` | 999px | 상태 뱃지, 역할/용도 태그 |

| 토큰 | 값 | 용도 |
|---|---|---|
| `--border-default` | `1px solid var(--color-line)` | 표, 패널, 입력 |
| `--border-strong` | `1px solid var(--color-line-strong)` | 입력 호버, 표 외곽 |
| `--shadow-overlay` | `0 8px 24px rgba(36, 24, 56, 0.16)` | 모달, 팝오버, 드로어, 토스트에만 사용 |

일반 패널과 카드에는 그림자를 쓰지 않는다.

### 4.4 아이콘
선 두께 1.5px, 20px 기준(16px는 표 안). 라이브러리는 Lucide 권장(라이선스 확인은 frontend). 아이콘 단독 버튼에는 `aria-label`과 툴팁.

## 5. 컴포넌트 토큰

### 5.1 버튼
| 종류 | 배경 | 글자 | 테두리 | 용도 |
|---|---|---|---|---|
| Primary | `brand` | `on-brand` | 없음 | 화면당 하나. [업로드], [차량 매칭으로], [견적서 생성], [저장] |
| Secondary | `surface` | `ink` | `line-strong` | [취소], [내보내기], [변경] |
| Ghost | 투명 | `brand` | 없음 | 표 안 보조 동작, [요구사항 추가] |
| Danger | `surface` | `#A82828` | `#A82828` | [삭제], [재분석] 확인 모달의 실행 버튼은 배경 채움 |

| 크기 | 높이 | 가로 패딩 | 글자 |
|---|---|---|---|
| sm | 32px | 12px | `small` 500 |
| md | 40px (기본) | 16px | `body` 500 |
| lg | 48px | 24px | `body` 600 |

- 호버: Primary는 `brand-hover`, Secondary는 배경 `surface-sunken`.
- 비활성: 배경 `surface-sunken`, 글자 `ink-faint`. 비활성인 이유는 옆 도움말이나 툴팁으로 알려 준다(예: "분석이 끝나면 볼 수 있습니다").
- 로딩: 글자 앞 16px 스피너, 너비 고정, 클릭 막음. 라벨은 진행형으로 바꾸지 않고 유지.
- 버튼 라벨은 **동사로 끝나거나 행선지를 말한다**. 같은 동작은 전체 흐름에서 같은 이름을 쓴다(흐름도의 버튼 이름 그대로).

### 5.2 포커스
모든 상호작용 요소: `outline: 2px solid var(--color-brand); outline-offset: 2px;` 입력은 테두리가 `brand`로 바뀌고 같은 아웃라인 추가. 포커스를 숨기지 않는다.

### 5.3 입력
- 높이 40px, 패딩 12px, `radius-data`, 테두리 `line`. 라벨은 입력 위, 14px 500. 필수 표시는 라벨 뒤 `(필수)` 텍스트. 별표만 쓰지 않는다.
- 도움말은 입력 아래 12px `ink-muted`. 오류는 같은 자리에서 `#A82828` + 오류 아이콘으로 바뀐다. 오류 문구는 무엇이 문제이고 어떻게 고치는지 말한다.
- 표 안 인라인 편집 셀: 평소엔 텍스트처럼 보이고, 호버 시 아래 점선, 포커스 시 입력 상자로 전환. 숫자 셀은 오른쪽 정렬 유지.

### 5.4 번호판 칩 (`PlateChip`)
차량 식별자를 번호판처럼 표시한다. 이 서비스의 시그니처 요소.
- 배경 `#FFFFFF`, 글자 `ink` 700, 테두리 `2px solid ink`, `radius-data`, 패딩 `2px 8px`, `13px`, `tabular-nums`, `letter-spacing: 0.04em`.
- 예: `12가 3456`. 번호판 정보가 없으면(수동 추가 항목) 회색 점선 테두리로 `번호 미정`.
- 선택된 카드 안에서도 칩 색은 바꾸지 않는다(식별성 유지).

### 5.5 씬 번호 (`SceneNumber`)
- Big Shoulders 800, 40px, `ink`. 폭 고정 56px, 오른쪽 정렬해 자릿수가 달라도 줄이 맞는다.
- 씬 목록 왼쪽에 세로로 놓고, 그 오른쪽에 장소/시간대를 둔다. 씬 사이는 2px `ink` 가로선이 아니라 1px `line`으로 나눈다(슬레이트 줄무늬 같은 장식은 쓰지 않는다).

### 5.6 태그 (역할, 용도)
알약 모양(`radius-pill`), 높이 24px, 13px 500, 아이콘 14px + 텍스트.

| 값 | 표시 | 모양 |
|---|---|---|
| 주인공 차 (LEAD) | 채운 점 ● + "주인공" | 배경 `brand-soft`, 글자 `brand-press` |
| 조연 차 (SUPPORT) | 반쯤 채운 점 ◐ + "조연" | 배경 `surface`, 테두리 `brand`, 글자 `brand-press` |
| 배경 차 (BACKGROUND) | 빈 점 ○ + "배경" | 배경 `surface-sunken`, 글자 `ink-muted` |

| 용도 | 아이콘 | 비고 |
|---|---|---|
| 일반 주행 (NORMAL) | 도로 | 중립 색 |
| 추격 (CHASE) | 속도선 | 중립 색 |
| 액션 (ACTION) | 번개 | 중립 색 |
| 파손 (DAMAGE) | 균열 | 위험색 짝. 파손 예정이면 항상 위험색으로 눈에 띄게 |

### 5.7 상태 뱃지
알약, 높이 24px, 아이콘 + 텍스트.

| 상태 | 문구 | 색 | 아이콘 |
|---|---|---|---|
| UPLOADED | 대기 | 중립 | 시계 |
| ANALYZING | 분석 중 | 진행 | 회전 스피너 |
| ANALYZED | 분석 완료 | 성공 | 체크 |
| FAILED | 분석 실패 | 오류 | 경고 |
| 견적서 DRAFT | 초안 | 중립 | 연필 |
| 견적서 REVIEW | 검토중 | 주의 | 눈 |
| 견적서 SENT | 발송 | 진행 | 종이비행기 |
| 견적서 CONFIRMED | 확정 | 성공 | 체크 |

### 5.8 신뢰도 표시 (`Confidence`)
LLM 추출 결과의 신뢰도(`confidence`, 0~1)를 3단계로 나눈다. 기준값은 제안이며 llm/backend와 조정한다.

| 단계 | 범위 | 표시 |
|---|---|---|
| 높음 | 0.80 이상 | 체크 아이콘 + "높음" (성공색) |
| 확인 필요 | 0.50 ~ 0.79 | 느낌표 아이콘 + "확인 필요" (주의색) |
| 낮음 | 0.50 미만 | 경고 아이콘 + "낮음" (오류색) |

- 숫자(`0.82`)는 호버 툴팁에만 보여 준다. 담당자에게 중요한 것은 확인할지 말지다.
- 수정한 행은 신뢰도 대신 **"수정함"** 표시(`brand-soft` 배경 알약, 연필 아이콘). 사람이 확인한 값이라는 뜻.

### 5.9 점수 막대 (`ScoreBar`, 매칭 점수)
- 높이 6px, 길이 64px, 트랙 `surface-sunken`, 채움 `brand`. 오른쪽에 숫자(0~100, 탭 숫자) 14px 600.
- 채움색은 점수와 무관하게 `brand` 하나. 점수 높낮이는 길이와 숫자로 읽는다(색 의미 과부하 방지).

### 5.10 원문 인용 블록 (`SourceQuote`)
- 배경 `surface-sunken`, 왼쪽 3px `brand` 막대, `radius-data`, 패딩 12px 16px, `text-reading`, `max-width: 68ch`.
- 차량 언급 구간은 `<mark>`로 `--color-highlight` 배경, 글자 `ink`, 패딩 `0 2px`.
- 인용 아래 출처: "씬 12 원문 중" `caption` `ink-muted`.

### 5.11 표 (`DataTable`)
- 헤더 행 배경 `surface-sunken`, 글자 `ink-muted` 13px 500, 높이 40px, 하단 선 `line-strong`.
- 본문 행 높이 48px(밀도 높은 편집 표는 44px), 행 사이 `line`. 호버 시 배경 `#FBFAFE`. 선택된 행 `brand-soft`.
- 숫자 열 오른쪽 정렬 + `tabular-nums`. 열 제목도 같이 오른쪽 정렬.
- 표 바깥 외곽선 `border-default`, `radius-data`. 가로가 넘치면 표만 가로 스크롤하고 첫 열(차량/씬)은 고정.
- 행 클릭 이동이 있는 목록은 행 전체가 링크 영역이고, 키보드로는 첫 셀의 링크에 포커스가 간다.

### 5.12 모달, 드로어, 팝오버, 토스트
| 요소 | 규격 |
|---|---|
| 모달 | 너비 480(확인) / 720(선택), `radius-overlay`, `shadow-overlay`, 배경 막 `rgba(36,24,56,0.48)`. 포커스 가둠, ESC 닫기. 제목은 질문이 아니라 무슨 일이 일어나는지: "대본을 삭제합니다" |
| 드로어 | 오른쪽에서 열림, 너비 480, 배경 `surface`. 원문 보기에 사용 |
| 팝오버 | 너비 320, 추가 비용 편집 등 작은 폼 |
| 토스트 | 화면 하단 중앙, 4초. 동작 이름을 그대로 반복: [저장] → "저장했습니다". 오류 토스트는 사라지지 않고 닫기 버튼 |

확인 모달 문구는 결과를 구체적으로 쓴다. 삭제: "대본 '서울의 밤' 원본과 분석 결과, 견적서가 모두 삭제됩니다. 되돌릴 수 없습니다." 버튼은 [삭제] / [취소].

### 5.13 배너
화면 상단 또는 패널 상단에 쓰는 한 줄 안내. 아이콘 + 문장 + (선택) 동작 링크. 주의/오류/정보 3종. 사라지는 것이 아니라 상태가 바뀌면 사라진다.

### 5.14 빈 상태
가운데 정렬(예외 허용), 상단 여백 64px, 제목(h3) 한 줄 + 설명 한 줄 + Primary 버튼 하나. 일러스트는 쓰지 않는다. 예: "아직 업로드한 대본이 없습니다 / 대본을 올리면 씬별로 필요한 차량을 정리해 드립니다 / [새 대본 업로드]"

## 6. 모션

사용자 동작과 무관하게 움직이는 것은 **하나만** 허용한다.

- **분석 완료 순간**: 대본 상세 화면에서 분석 단계 4개가 순서대로 체크되고(각 120ms, 간격 80ms), 분석 결과 버튼이 활성화된다. 한 번만 재생.

사용자 동작에 반응하는 모션
| 동작 | 모션 |
|---|---|
| 씬/요구사항 펼치기 | 높이 + 불투명도 160ms ease-out |
| 모달/드로어 열기 | 불투명도 + 8px 이동 180ms |
| 항목 추가/삭제 | 행이 접히며 사라짐 160ms |
| 합계 금액 변경 | 숫자 즉시 교체, 0.6초간 배경 `brand-soft` 깜빡임으로 변경 위치만 알림 |

`prefers-reduced-motion: reduce`에서는 모든 이동을 없애고 불투명도 변화 또는 즉시 전환만 쓴다. 스크롤 진입 애니메이션, 카드 호버 들썩임은 만들지 않는다.

## 7. 접근성 기준

- 글자 대비 AA 이상. 상태 정보는 색 + 아이콘 + 텍스트.
- 최소 터치/클릭 영역 32px(표 안 아이콘 버튼은 32 × 32). 모바일은 40px.
- 키보드만으로 업로드, 표 편집, 후보 선택, 견적서 저장까지 가능해야 한다. 표 안 셀은 Tab으로 이동, Enter로 편집, ESC로 취소.
- 분석 진행 상태 영역은 `aria-live="polite"`.
- 아이콘 단독 버튼, 씬 번호, 번호판 칩은 `aria-label`로 읽히는 문장을 제공.
- 폼 오류는 필드와 `aria-describedby`로 연결하고, 제출 실패 시 첫 오류 필드에 포커스.

## 8. 카피 원칙

- 존댓말(-습니다/-합니다), 문장형 명사구로 짧게. 사용자 입장의 말로 쓴다("임베딩" 대신 "차량 정보 반영").
- 같은 동작은 같은 이름: [업로드] → 토스트 "업로드했습니다". [저장] → "저장했습니다". [재분석] → "다시 분석을 시작했습니다".
- 오류는 사과하지 않고 원인과 해결 방법을 말한다. "PDF, DOCX, TXT 파일만 올릴 수 있습니다. 다른 형식이면 변환 후 다시 올려 주세요."
- LLM 결과임을 숨기지 않는다. 자동 추출 값에는 확인 상태(신뢰도 또는 "수정함")가 항상 따라붙는다. 자동 확정은 없다.
